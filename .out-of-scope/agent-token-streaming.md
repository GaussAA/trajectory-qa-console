# 智能体诊断的模型文本流式输出

本项目不把模型生成的文本以 token 流的形式推给界面。

## 为什么不做

界面在诊断运行中已经有进度反馈：`qa serve` 用 NDJSON 推送 `start → progress → done`，
面板显示第几轮、调了哪个工具、耗时（`AgentEvent` 的 `round` 与 `tool` 两种事件）。
缺的只是"模型正在写什么"，这一块是有意不报的：

- `AgentEvent` 的注释写明「只报事实，不报模型文本——那个在最后一次性给出，免得半截话被当成结论」。
- ADR-0019 把模型的自然语言单独成节并显式标注未核验，数字只来自工具。
  推送半截文本会让未核验的内容先于结论出现在界面上，与这条界限冲突。
- 收益只是体感延迟。进度事件已经让用户知道程序没有卡住。
- 代价不小：`core/agent/chat.ts` 要新增流式响应解析，`AgentEvent` 要新增文本增量事件，
  面板要处理未完成文本，而 ADR-0019 的取舍里已写明靠预算上限兜住、不做流式。

## 若要重新考虑

需要先翻案 ADR-0019 的上述取舍，并说明半截文本如何不被当成结论。
