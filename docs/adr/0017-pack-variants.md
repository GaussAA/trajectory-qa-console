# ADR-0017：规则包变体

日期：2026-10-23 ｜ 状态：已接受

## 背景

调参面板让「改阈值 → 看命中」变得很快，但结果只活在当前草稿里：想比较
「严格口径」和「宽松口径」，只能反复导出 JSON 再导入。调参的价值因此打折。

## 决定

- **变体存的是草稿，不是已应用的包。** 这是整个功能的意义所在：调完参数
  看一眼命中率满意，直接「存为变体」，不必先「校验并应用」。存前仍过
  `validatePack`，坏草稿存不进去。
- **深拷贝入档。** 存的是 `JSON.parse(JSON.stringify(pack))`——之后手改
  当前包，不会悄悄改掉已存的口径。
- **「生效中」按内容判定，不按会话。** `activeVariantId` 由 reducer 维护：
  `variant/save` 与 `variant/apply` 设置；经抽屉手改包（`pack/apply`）即清空
  ——内容已偏离，列表不再高亮，诚实的做法是承认它不再是那个变体。
- **删变体不动包。** 当前包保持原样（它仍是合法口径），只摘掉「来自变体」
  的标记——用户没要求回滚，别替他做决定。
- **`workspace/clear` 不清变体。** 变体是口径库，不是工作区草稿；清空会话
  不该把调好的口径一起带走。
- **上限 20 个**（`MAX_PACK_VARIANTS`）：变体应是少数几个精心调出的口径，
  不是杂物堆；超限给明确提示，不静默丢弃最旧的。

## 存储

`tqa.pack-variants`，与既有键同一信封（`schemaVersion`）。读取时**逐条**
`validatePack`：一条脏数据只丢自己，不拖垮整个列表。

## 已知边界

变体只在界面里；CLI 的 `--pack` 仍读文件——要把变体用于命令行，从抽屉
导出 JSON 即可（两者格式相同，变体不是新格式）。
