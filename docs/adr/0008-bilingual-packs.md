# ADR-0008 双语规则包：翻译文案，不翻译判定

- 状态：已采纳
- 日期：2026-10-22

## 背景

ADR-0006 把「规则包文本不随界面语言翻译」定为边界，代价是英文报告里规则标题与
详情仍是中文。这个代价可以用**数据**消掉：另做一份英文规则包，而不让代码去翻译。
关键风险是两份包慢慢漂移——id 对不上、表达式被顺手改掉、某条规则只翻了一半。

## 决定

1. **JSON 是唯一事实来源**：`packs/builtin-en.json` 是完整包（维度 + 规则），
   `src/core/rules/builtin-pack-en.ts` 只做 `validatePack` 与导出，**不再抄一遍**。
   界面可以用同一份文件导入，命令行用 `--pack en` 读同一份。
2. **只翻文案**：`id / dimension / severity / scoreImpact / scope / expr / enabled`
   与中文包逐条相等；翻译只动 `title`、`message`、维度 `label`、`description`、包名。
3. **占位符必须一致**：`{step}`、`{unpairedCalls}` 这类占位符按规则逐条比对。
   漏一个不会报错，却会让结论丢掉定位信息——这种「静默降级」只能靠测试拦。
4. **判定等价性由测试证明**：拿三条示例轨迹分别喂两个包，`runRules` 产出的
   `(ruleId, severity, stepIndex)` 序列必须完全相同。翻译改坏逻辑，这里立刻红。
5. **别名而非隐式切换**：`--pack en` / `zh` / `builtin-en` 是显式选择，
   `--locale en` **不会**偷偷换包——语言与规则口径是两件事，这也守住了 ADR-0006。

## 取舍

- 为什么不做运行时翻译层（把中文规则文案塞进字典）：规则包是用户可替换的数据，
  用户自定义包里的中文无法翻译；翻译层只对内置包有效，会造成「内置能翻、自定义不能」的
  假象。双语包则对任何来源一视同仁。
- 为什么不把英文包设成默认：项目的中文语料与团队协作以中文为主，默认应当是母语口径。
- 代价：新增规则要改两个文件。用结构测试把「漏改」变成红灯，比靠记性可靠。

## 后果

- `--pack en --locale en` 产出的报告里**一个中文字都没有**（冒烟脚本直接断言字节内容）。
- 两份包共 24 条规则、4 个维度，任何一侧增删规则都会触发结构测试失败。
- 界面暂未内置语言包切换：用户仍可通过规则抽屉「导入」`packs/builtin-en.json`。
  若要在界面里一键切换，需要新增控件，属独立的界面变更。
