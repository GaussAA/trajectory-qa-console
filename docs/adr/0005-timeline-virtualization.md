# ADR-0005：大轨迹的时间线改用固定行高虚拟滚动 + 概览条降采样

- 状态：已采纳
- 日期：2026-10-22

## 背景

分析 10k 步只需约 100ms，但时间线会一次性挂载 10k 行（每行含角色、预览、token 条、问题徽标）与 10k 个概览刻度。仅这两处就是两万个节点，浏览器布局与绘制会卡住数秒，滚动也掉帧。性能瓶颈不在核心算法而在渲染。

## 决策

1. **阈值**：步数 > 400 进入紧凑模式；≤400 保持原样（视觉零变化，golden 截图可证）。
2. **虚拟滚动**：紧凑模式行高固定 46px，只渲染可视区 + 上下各 6 行 overscan；`computeWindow()` 为纯函数，带边界钳制与空列表处理。
3. **概览条降采样**：`bucketizeSteps()` 把任意步数压到 ≤180 段，每段记录覆盖区间、峰值 token（决定高度）、代表性角色与是否含 error。
4. **滚动职责内聚**：选中步骤的滚动由 Timeline 自己负责（虚拟模式下按 `index × rowHeight` 计算 scrollTop），App 不再跨组件查 DOM 节点。
5. **压力入口**：`#stress:N` 生成 N 步合成轨迹，供手工与截图验证；不占界面。

## 后果

- 10k 步下常量级 DOM（约 26 行 + 180 段），jsdom 测试断言行数 <60；
- 紧凑模式牺牲了每行的工具 chip 与解析备注（信息仍在右侧检视器中）；
- 固定行高换来可预测的窗口计算；若未来需要可变行高，须改用测量式窗口并单独记录决策；
- 概览条从「每步一柱」变为「区间一柱」，颜色取该区间峰值角色，error 区间强制红色。
