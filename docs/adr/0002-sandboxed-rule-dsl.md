# ADR-0002：规则表达式采用沙箱 DSL，并在编译期校验契约

- 状态：已采纳
- 日期：2026-10-22

## 背景

规则是用户可编辑的数据，会被导入导出。若用 `eval` / `new Function` 求值，粘贴一份规则包就等于执行任意代码；若只在求值时发现字段拼错，错误要等到某条轨迹恰好命中才会暴露。

## 决策

自研表达式语言（`src/core/expr.ts`）：

1. 词法 → AST → 求值三段式，禁用 `eval`；
2. 编译结果暴露 `identifiers`，供契约在**保存前**比对合法字段；
3. 未知字段给出最近匹配建议（编辑距离 ≤2）；
4. 限制源长度 1000、AST 节点 400、嵌套 40，阻断病态表达式；
5. 屏蔽 `__proto__` / `constructor` 等属性访问；
6. 函数白名单（len / includes / any / all / count / sum / round …），未知函数在编译期报错。

## 后果

- 规则包错误定位到 `rules.3.expr` 这样的路径，用户可自助修正；
- 字段契约由编译期类型守卫（`Record<keyof StepContext, FieldType>`）保证完整性，并有测试比对运行时上下文键集合；
- 代价是需要维护一个小型解释器；语言能力受限（无闭包、无循环），但这正是规则应有的表达力边界。
