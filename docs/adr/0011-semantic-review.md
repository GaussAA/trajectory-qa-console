# ADR-0011 语义复核：只在命令行调模型，密钥只从环境变量读

- 状态：已采纳
- 日期：2026-10-22

## 背景

四个维度里，只有「语义质量」还是启发式 + 人工标注。要补上「答非所问 / 无依据断言 /
越权承诺」，必须让模型读轨迹。问题不在于会不会调 API，而在于**在哪儿调、密钥放哪、
失败怎么办**。

## 决定

1. **只做 CLI，不进浏览器。** 单文件 HTML 的立身之本是「双击可用、零联网」。在界面里
   接模型会同时破坏三件事：离线承诺、CORS（多数供应商不允许浏览器直连）、以及密钥
   托管（`localStorage` 里的 key 任何人都能读）。界面继续只吃规则结论。
2. **密钥只从 `TQA_LLM_API_KEY` 读。** 不接受 `--api-key` 参数：命令行会进 shell history
   与进程列表。地址与模型可以从参数或 `TQA_LLM_URL` / `TQA_LLM_MODEL` 取。错误信息里
   只出现状态码与响应前 200 字，**绝不回显密钥**——有测试专门断言这一点。
3. **显式开启，失败降级。** `--semantic` 默认关闭；开启后单次调用失败只记一条 issue，
   整批继续、退出码不变。语义是加分项，不该让一次 429 把整个门禁判死。
4. **先试跑，再花钱。** `--semantic-dry-run` 只打印将要发送的两条消息，不调用模型。
   审计提示词、复盘「模型凭什么这么判」、离线检查都能用，且零成本。
5. **预算前置。** `--semantic-limit`（默认 20 个会话）、单会话最多 8 条判定、
   超长轨迹按「问题步优先 + 等距采样」压到 120 步。跳过就是跳过（返回 `null`），
   不会把自己算进「已复核」。
6. **输出契约宽进严出。** 提示词写死类别与字段；解析层再去掉代码围栏、容忍裸数组、
   校验枚举、把越界步号降级为「无步号」而不是编个位置。

## 取舍

- 为什么不让 UI 调模型：见上。若日后要做，正确形态是「本地小服务 + 浏览器调本机」，
  而不是把 key 塞进页面。
- 为什么不做多轮自检（让模型复核自己的判定）：成本翻倍、收益不确定，且会让
  「同一输入同一结论」这条可复现性更难保证。
- 为什么语义判定不与规则判定去重：两者口径不同（规则看结构，模型看语义），
  同一步上同时命中恰恰说明问题确凿，报告里并列展示更有说服力。
- 已知代价：模型输出不稳定时，分数会随模型漂移。这一点无法用代码消除，只能靠
  `temperature: 0`、固定提示词与 dry-run 审计把变量压到最小。

## 后果

- 新增 `src/core/semantic/`：`prompt`（摘要与契约）、`parse`（容错解析）、
  `judge`（超时/重试/取消）、`merge`（并入评分）、`types`（可注入传输层）。
- CLI 新增 `--semantic` / `--semantic-dry-run` / `--llm-url` / `--llm-model` / `--semantic-limit`。
- `runBatch` 改为异步并接受 `semantic` 钩子；`scoreSession` 增加 `extra` 形参承载外部 findings。
- 测试：语义核心 16 项、CLI 语义路径 5 项、冒烟 2 项（试跑与缺配置）。
- 界面零改动——这是本轮刻意的边界，不是遗漏。
