# ADR-0014 批量选择：前缀 + 序号，不做逐条输入

- 状态：已采纳
- 日期：2026-10-22

## 背景

一次导入十几条轨迹（同一任务的多次实验）时，单条改名要重复十几次，而且每次都要
想名字。真正需要的是「共性进前缀、差异进序号」：`exp-01`、`exp-02`…

## 决定

1. **批量命名 = 前缀 + 起始序号 + 补零位数**，实时预览结果。
   `buildBatchNames(count, naming)` 是纯函数，界面只负责取值与展示。
   没有前缀时退化为纯序号（`01`、`02`），补零位数上限 6——防止有人输入 99 位造出长串。
2. **一次 dispatch 提交多条。** `note/batch` 合并进 `notes`，避免 N 次渲染与 N 次
   评分重算。合并时统一 trim；空名称 + 空备注表示「这条不要名字了」，
   与单条编辑的语义保持一致。
3. **删除必须二次确认。** 第一次点击把按钮变成「确认删除 N 条」，第二次才执行；
   不做浏览器 `confirm` 弹窗（阻塞、不可测、样式不可控）。
4. **删除后选中态必须自洽。** `session/remove` 会重新落点：优先保留原选中项，
   它被删了就落到剩余第一条，并按新会话重算「首个问题步」；全删则回到 `idle`。
   `SessionList` 里还会把已不存在的选中项从集合里剔掉。
5. **选择态是临时 UI 状态，不进 reducer。** 它不持久化、不影响评分、不影响导出；
   放本地 state 可以避免污染工作区状态机。

## 取舍

- 为什么不做「逐条输入名称」的批量弹窗：十个输入框在小面板里既挤又慢，
  而且与单条改名重复；前缀 + 序号覆盖了真实场景的 90%。
- 为什么不支持正则替换：那是编辑器的事，不是质检台的事。
- 为什么删除不做撤销：会话是解析产物，重新导入即恢复；做撤销栈的复杂度不匹配。
- 已知边界：批量备注对所有选中项写同一段文字，不能一条一注；单条差异仍需单独编辑。

## 后果

- `lib/naming.ts` + 6 项单测（前缀、起始、补零、空前缀、非正数、补零上限）。
- `workspace` 新增 `note/batch` 与 `session/remove`，5 项单测覆盖合并/清空/删后选点/全删/幽灵 id。
- `SessionList` 增加选择开关、复选框、批量操作条与批量表单；2 项 App 级交互测试
  （批量命名生效、删除需二次确认）。
- 面板宽度仅 258px，因此批量字段加了 8.5px 的标签行——占位符一旦有值就失去说明作用。
